# node.js
```javascript
const http = require('http');

http.createServer((req, res) => {
    // 1. URLSearchParams를 사용하여 쿼리 문자열을 더 현대적인 방식으로 파싱합니다.
    const requestUrl = new URL(req.url, `http://${req.headers.host}`);
    const query = requestUrl.searchParams;

    // 2. GET 파라미터를 가져오고, 값이 없거나 숫자가 아닐 경우 0으로 기본값을 설정합니다.
    const name = query.get('userName') || '이름없음';
    const html = parseInt(query.get('htmlScore')) || 0;
    const css = parseInt(query.get('cssScore')) || 0;
    const node = parseInt(query.get('nodeScore')) || 0;
    const android = parseInt(query.get('andScore')) || 0;

    const avg = (html + css + node + android) / 4;

    res.writeHead(200, {
        'Content-Type': 'text/html; charset=utf-8'
    });

    // 3. 학점 계산 로직을 배열과 find 메서드를 사용하여 개선합니다.
    // 이렇게 하면 학점 기준이 변경될 때 유지보수가 더 쉬워집니다.
    const gradeThresholds = [
        { score: 95, grade: 'A+' },
        { score: 90, grade: 'A' },
        { score: 85, grade: 'B+' },
        { score: 80, grade: 'B' },
        { score: 75, grade: 'C' },
    ];

    const foundGrade = gradeThresholds.find(threshold => avg >= threshold.score);
    const grade = foundGrade ? foundGrade.grade : 'F';

    // 4. HTML 응답에 CSS를 추가하여 li 태그의 점(bullet point)을 제거하고 가독성을 높입니다.
    const responseBody = `
    <style>
        body { font-family: sans-serif; }
        ul {
            list-style-type: none;
            padding-left: 0;
        }
        li {
            padding: 4px 0;
        }
    </style>
    <h2>성적 결과</h2>
    <ul>
        <li>이름 : ${name}</li>
        <li>HTML : ${html}</li>
        <li>CSS : ${css}</li>
        <li>Node.js : ${node}</li>
        <li>Android : ${android}</li>
        <li><b>평균 : ${avg.toFixed(2)}</b></li>
        <li><b>학점 : ${grade}</b></li>
    </ul>
    `;

    res.end(responseBody);
}).listen(3000, () => {
    console.log('Server is running at http://localhost:3000');
});
```

### 1. 이전 방식: url.parse(req.url, true).query
이 코드는 다음과 같이 동작합니다.

1. req.url에는 /ex06.html?userName=... 와 같은 경로와 쿼리 문자열이 담겨 있습니다.
2. url.parse(req.url, true)는 이 문자열을 분석합니다.
3. 두 번째 인자인 true는 쿼리 문자열(? 뒷부분)을 자바스크립트 객체(Object) 형태로 만들어달라는 의미입니다.
4. .query를 통해 이 객체에 접근합니다.
결과적으로 query 변수에는 다음과 같은 일반적인 자바스크립트 객체가 할당됩니다.

```
{
  userName: '홍길동',
  htmlScore: '95',
  cssScore: '88',
  // ...
}
```

### 2. 새로운 방식: new URL()과 query.get()
이 코드는 더 현대적이고 표준적인 방식으로 동작합니다.

1. new URL(req.url, baseURL)은 완전한 URL 구조를 분석하여 URL 객체를 생성합니다.
  - req.url에는 /로 시작하는 경로만 있으므로, http://localhost:3000 같은 baseURL을 함께 제공하여 완전한 URL로 만들어줍니다.
2. 생성된 URL 객체는 searchParams라는 특별한 속성을 가집니다.
3. 이 searchParams는 URLSearchParams라는 **전용 도구(객체)**입니다. 일반 객체와는 다릅니다.
4. 이 도구는 쿼리 문자열을 다루기 위한 여러 편리한 **메서드(기능)**를 내장하고 있습니다. 값을 가져올 때는 get() 메서드를 사용해야 합니다.
query.get('htmlScore')는 "searchParams 도구야, 'htmlScore'라는 이름표가 붙은 값을 찾아줘!" 라고 명확하게 요청하는 것과 같습니다.

왜 새로운 방식이 더 좋은가요?
단순히 값을 가져오는 현재 코드에서는 두 방식의 차이가 커 보이지 않을 수 있습니다. 하지만 새로운 URLSearchParams 방식은 다음과 같은 명확한 장점이 있습니다.

1. 표준이라서 좋습니다: 웹 브라우저에서도 똑같이 동작하는 표준 방식입니다. 코드가 더 일관성 있고, 다른 개발자가 이해하기 쉽습니다.
2. 의도가 명확합니다: query.get('name')은 "name 파라미터의 값을 가져온다"는 의도를 코드만 봐도 명확하게 알 수 있습니다.
3. 강력하고 안전합니다: 만약 ?subject=math&subject=eng처럼 같은 이름의 파라미터가 여러 개 있다면, query.get('subject')는 첫 번째 값('math')만 가져옵니다. 모든 값을 배열로 가져오고 싶으면 query.getAll('subject')를 쓰면 됩니다. 레거시 방식으로는 이런 처리가 더 복잡합니다.
4. 미래 지향적입니다: Node.js 공식 문서에서도 url.parse()는 **레거시(Legacy)**로 분류되어 있습니다. 즉, 언젠가는 지원이 중단될 수 있으며 새로운 표준 API 사용을 권장하고 있습니다.
결론적으로, query.get()을 사용하는 것은 단순히 문법만 다른 것이 아니라, 더 안정적이고 표준적이며 기능이 풍부한 최신 도구를 사용하는 것입니다. 좋은 습관을 들이는 것이죠!
