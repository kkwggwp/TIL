### 신경망 설계
#### 1. `nn.Sequential`을 Class 없이 사용
```python
model2 = nn.Sequential(
    nn.Linear(input_size, 500),
    nn.ReLU(),
    nn.Linear(500, 400),
    nn.ReLU(),
    nn.Linear(400, 300),
    nn.ReLU(),
    nn.Linear(300, 200),
    nn.ReLU(),
    nn.Linear(200, 100),
    nn.ReLU(),
    nn.Linear(100, 50),
    nn.ReLU(),
    nn.Linear(50, output_size),
    nn.LogSoftmax(dim=1)
)
```
1. `nn.Sequential`을 사용해 모델만 정의한 경우는 코드가 짧고 직관적이지만 유연성이 매우 부족함
2. 아주 간단한 계산을 구현하는 프로토타이핑 아니면 이대로 사용을 권장하지 않음

#### 2. `nn.Sequential`을 Class로 구현시
```python
class MyModel(nn.Module):
    def __init__(self, input_dim, output_dim):
        super().__init__()
        self.input_dim = input_dim
        self.output_dim = output_dim
        self.model = nn.Sequential(
            nn.Linear(input_size, 500),
            nn.ReLU(),
            nn.Linear(500, 400),
            nn.ReLU(),
            nn.Linear(400, 300),
            nn.ReLU(),
            nn.Linear(300, 200),
            nn.ReLU(),
            nn.Linear(200, 100),
            nn.ReLU(),
            nn.Linear(100, 50),
            nn.ReLU(),
            nn.Linear(50, output_size),
            nn.LogSoftmax(dim=1)
        )  
    def forward(self, X):        
        return self.model(X)

model = MyModel(input_dim=input_size, output_dim=output_size)
```
1. 비교적 유연성이 높다
2. 명확한 구조 및 가독성
3. 쉬운 디버깅
4. Class 사용하면 재사용성이 높다
5. `nn.Sequential`로 묶인 계층은 하나의 블랙박스로 취급되고 출력을 따로 빼내서 사용하는 중간 개입이 어려움

#### 2.1 Class를 사용해 모든 레이어를 개별적으로 정의
```python
class MyModule(nn.Module):
    def __init__(self, input_dim, output_dim):
        super().__init__()
        self.input_dim = input_dim
        self.output_dim = output_dim
        self.linear1 = nn.Linear(input_dim, 500)
        self.linear2 = nn.Linear(500, 400)
        self.linear3 = nn.Linear(400, 300)
        self.linear4 = nn.Linear(300, 200)
        self.linear5 = nn.Linear(200, 100)
        self.linear6 = nn.Linear(100, 50)
        self.linear7 = nn.Linear(50, output_dim)
        self.act_lelu = nn.ReLU()
        self.act_logsoftmax = nn.LogSoftmax()

    def forward(self, x):
        h = self.act_lelu(self.linear1(x))
        h = self.act_lelu(self.linear2(h))
        h = self.act_lelu(self.linear3(h))
        h = self.act_lelu(self.linear4(h))
        h = self.act_lelu(self.linear5(h))
        h = self.act_lelu(self.linear6(h))
        y = self.act_logsoftmax(self.linear7)

        return y

model1 = MyModule(input_size, output_size)
```
1. 유연성이 높음
    * 위 방식과 비교해 `forward` 메서드 내에서 linear와 lelu를 따로 정의해 출력(`h`)에 언제든지 접근 가능
    * 스킵 커넥션 : `h1 = self.linear1(x)`의 결과를 나중에 `self.linear3`의 출력에 더해주는 식의 구현이 가능
    * 다양한 데이터 흐름: 중간 출력을 다른 모델의 입력으로 사용하거나, 로깅, 시각화 등 원하는 모든 작업을 수행할 수 있습니다.
    * 쉬운 디버깅 : `forward` 함수 내부에 `print(x.shape)`같은 코드를 자유롭게 추가해 확인 가능
2. 모델 내부에서 단순히 순차적으로만 작동하는 명확한 블록이 있다면 `nn.Sequential`을 사용해 깔끔히 코드 작성 가능
    * 예를 들어, "인코더" 부분이 3개의 Linear-ReLU 쌍으로 이루어져 있다면,
    * `self.encoder = nn.Sequential(...)`로 정의하고, `forward`에서는 `encoded_features = self.encoder(x)` 한 줄로 처리하는 것
